---
title: "Page-Level Access"
description: "Understand public, protected, and paid-access routes in the boilerplate."
---

The boilerplate is private by default. Middleware in `src/middleware.ts` whitelists public routes and redirects everything else to login.

## Access levels

| Level | Requirement | Redirect on failure | Examples |
| --- | --- | --- | --- |
| Public | None | None | `/`, `/home`, `/pricing`, `/blog/*`, legal pages, auth pages |
| Protected | Signed-in user | `/login` | `/account/*`, most app routes |
| Access-gated | Signed-in user plus subscription/order access | `/choose-plan` | `/dashboard` by default |

## Public routes

Public exact routes and prefixes are defined in middleware:

```ts
const PUBLIC_ROUTES = [
  routes.home,
  routes.homeRedirect,
  routes.pricing,
  routes.auth.signup,
  routes.auth.login,
  routes.auth.forgotPassword,
  routes.auth.resetPassword,
  routes.legal.termsOfService,
  routes.legal.privacy,
];

const PUBLIC_ROUTE_PREFIXES = [routes.blog];
const AUTH_API_PREFIX = "/api/auth";
```

## Landing mode

When `LANDING_MODE=true`, middleware redirects most traffic to `/landing`. Legal pages remain accessible.

```ts
const LANDING_MODE_ALLOWED_ROUTES = [
  routes.landing,
  routes.legal.termsOfService,
  routes.legal.privacy,
];
```

## Paid access gate

`REQUIRE_ACCESS_ROUTES` controls which authenticated pages require paid access. The default model checks for an active subscription:

```ts
const REQUIRE_ACCESS_ROUTES: string[] = [routes.dashboard];
const hasUserAccess = await hasActiveSubscription(userId);
```

You can switch to one-time purchase or hybrid access by using `hasActiveOrder` from `@/features/benefits` or combining both checks. Keep the docs and product copy aligned with whichever business model you choose.

## Server-side protection patterns

Use the supported helpers instead of hand-rolling session parsing:

- Page guard: `auth.api.getSession({ headers: await headers() })`.
- Server query: `authed.query(...)`.
- Server action: `authed.action(...)`.
- Route handler: `authed.route(...)`.

See [Server Utilities](/features/server-utilities) and [Authentication Overview](/authentication).
