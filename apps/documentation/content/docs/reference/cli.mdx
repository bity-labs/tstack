## Current status

The CLI is retained in `packages/cli`, but v2 scaffolding is not implemented yet. It does not install the new brain, assistant, OS, or three-app boilerplate.

| Command | Status |
| --- | --- |
| `tstack init` | Unavailable; exits with an explanatory message without creating a project |
| `tstack ready` | Legacy production environment wizard for existing compatible projects |
| `tstack products` | Legacy Polar product management and local billing generation for existing compatible projects |

The legacy commands are not a completed v2 setup workflow. Their presence does not establish provider choices for the new boilerplate.

## Local use

From the TStack repository root:

```sh
pnpm tstack --help
pnpm tstack init --help
```

## Optional global link

The CLI is private and is not published to public npm. Publishing is outside this documentation cleanup.

```sh
pnpm run setup
tstack --help
```

`setup` builds and globally links the CLI. It does not enable v2 scaffolding. The checkout must remain on disk while the linked binary is in use. To unlink it, run `pnpm tstack:unlink` from the repository root.

## Existing projects only

The retained commands default to the current directory. Point them at an existing compatible project, not a v2 placeholder:

```sh
tstack ready --project-dir /path/to/existing-project
tstack products --project-dir /path/to/existing-project
```

`ready` writes `.env.production`; it does not deploy or provision infrastructure. `products` defaults to Polar sandbox and can modify remote products. Local billing generation still expects the previous starter's configuration layout. Meter synchronization remains manual.

For full legacy configuration instructions, see the [v1 CLI guide](https://github.com/bity-labs/tstack/blob/v1/apps/documentation/content/docs/reference/cli.mdx).
