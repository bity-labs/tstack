## `tstack init` reports that scaffolding is unavailable

This is intentional: v2 scaffolding is not implemented yet. Linking or rebuilding the CLI does not create a missing starter. For the previous application, use the [preserved v1 documentation](https://github.com/bity-labs/tstack/tree/v1/apps/documentation/content/docs).

## A new component has no development command

The new boilerplate apps, brain, assistant, and OS directories contain only README placeholders. There are no package manifests or runtime scripts to execute yet.

## `tstack` is not found

From the repository root, use `pnpm tstack --help` after installing dependencies. Global linking with `pnpm run setup` is optional; see [CLI status](/reference/cli). A globally linked command depends on its source checkout remaining on disk.

## Documentation validation looks incomplete

The documentation test and lint scripts currently print a placeholder message. Use `pnpm --filter @tstack/documentation typecheck` and `pnpm --filter @tstack/documentation build` for implemented validation.

## Harness links do not resolve

In this monorepo, root `.agents` and `docs/engineering` should resolve into `packages/harness/templates/default`. Keep those source assets intact. In an installed project, replace links back to TStack with real copied files and customize project-owned context; see [harness installation](/harness/installation).
