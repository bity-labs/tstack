This is an advanced/niche setup for products where the thing being sold is code access, such as a private repository, starter kit, or template.

## Why simplify auth to GitHub?

When selling code access, GitHub identity matters:

- customers already need a GitHub account,
- Polar GitHub benefits can grant repository access after purchase,
- password, OTP, and wallet login can add friction without helping the core flow.

## Recommended target shape

- Keep GitHub OAuth.
- Keep Polar checkout and benefits.
- Keep account deletion only if you have a safe email/contact policy.
- Remove or hide unused auth methods from public UI.
- Make the paid access page explain how the customer connects GitHub in the Polar portal.

## Implementation prompt for an agent

Use this prompt with your coding agent after you decide GitHub-only auth is right for your product:

```markdown
You are simplifying this TStack Agent-Ready Boilerplate app to use only GitHub OAuth for a code-access product.

Explore first:
1. Better Auth server config and plugins under `src/lib/auth/`.
2. Auth client config in `src/lib/auth-client.ts`.
3. Auth components and hooks under `src/features/authentication/`.
4. Auth pages under `src/app/(auth)/`.
5. Wallet config/providers if SIWE is present.
6. Email templates and hooks used only by removed auth flows.
7. Middleware public routes.
8. Locales and navigation copy.
9. Package dependencies that become unused.

Clarify before editing:
1. Should account deletion still require email verification?
2. Should unused dependencies be removed now or in a follow-up?

Implement in small steps:
1. Keep GitHub provider configuration and remove unused auth methods from public UI.
2. Remove email/password, OTP, Twitter, and SIWE flows only if the owner confirms.
3. Update middleware public routes if forgot/reset password pages are removed.
4. Update locales, docs, tests, and package dependencies to match.
5. Run typecheck, tests, and build.
```

## Polar benefit setup

1. Create a one-time or subscription product in Polar.
2. Add a GitHub repository benefit in Polar.
3. Configure the product in `polar/products.sandbox.json` and `polar/products.production.json`.
4. Keep generated billing files aligned with product JSON.
5. Test that `GitHubBenefitsList` shows grant status after purchase.

## Buyer support copy

Tell customers:

- which GitHub account they must sign in with,
- whether repository access is instant or requires connecting GitHub in Polar,
- where to find the customer portal,
- how to contact support if access is pending.
