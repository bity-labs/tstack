---
title: "Known Limitations"
description: "Current boundaries of the standalone harness."
---

## Manual installation

The standalone harness is copied manually from `packages/harness/templates/default`. There is no TStack CLI installer, package hook, or migration helper yet.

## Placeholder project context

The default `docs/context.md` and `docs/coding-standards.md` include placeholders. Replace them with real project information before relying on the harness for product or engineering decisions.

## Symlinks are development-only

The TStack monorepo dogfoods harness-owned assets through symlinks so local edits update the product template. Installed projects should receive real copies of every harness file, not symlinks back to the TStack source tree.

## No automated boilerplate scaffold yet

The Agent-Ready Boilerplate exists in `apps/boilerplate`, but there is no CLI command that creates a standalone app from it yet. Until that exists, start from the monorepo source or copy the app manually and materialize linked harness assets as real files.

## No vendor-specific adapters

Skills are plain Markdown workflows. The harness does not currently ship generated slash commands, tool-specific extension packages, or automatic agent configuration.

## No automation for deployment or releases

The harness does not set up payment providers, deployment infrastructure, release automation, repository access, or branch protection.

## Docs may lag project reality unless maintained

The harness works best when `docs/context.md`, `docs/coding-standards.md`, ADRs, and skills are updated as the project changes. Outdated documentation can mislead agents.
