title: "Managed Deployment / Vercel + Prisma"
description: "Deploy the boilerplate to a managed Next.js host with a managed PostgreSQL database."
---

This recipe targets Vercel-style managed hosting plus Prisma/PostgreSQL. Adapt the same ideas to any managed host that supports Next.js, pnpm, and environment variables.

## Prerequisites

- A GitHub repository containing either the TStack monorepo or a manually extracted standalone boilerplate app.
- A Vercel account.
- A managed PostgreSQL database, such as Prisma Postgres, Neon, Supabase, or another provider.

## Repository shape choices

### Current monorepo source

Keep the TStack repository layout and configure the managed host for `apps/boilerplate` as the app.

Typical settings:

| Setting | Value |
| --- | --- |
| Root directory | `apps/boilerplate` if the host supports workspace root detection, otherwise repository root with filtered commands. |
| Build command | `pnpm --filter @tstack/boilerplate build` from root, or `pnpm build` when the host runs inside the app directory. |
| Output | Next.js default. |

### Manually extracted standalone app

Deploy as a normal Next.js app:

```sh
pnpm install
pnpm build
pnpm start
```

## Database and migrations

Set `DATABASE_URL` to the managed database connection string.

Run production migrations as a release/deploy step:

```sh
pnpm --filter @tstack/boilerplate db:migrate
```

For standalone extraction:

```sh
pnpm db:migrate
```

Use `db:push` only for local development/prototyping, not production schema changes.

## Environment variables

Set production URLs after the first deployment or custom domain setup:

```sh
PROJECT_URL=https://myapp.example.com
NEXT_PUBLIC_SITE_URL=https://myapp.example.com
BETTER_AUTH_URL=https://myapp.example.com
```

Also configure provider variables for the features you use:

- Better Auth secret.
- Database URL.
- OAuth provider credentials.
- Polar token/server/webhook secret.
- Resend email settings.
- Analytics provider settings.
- File upload provider settings.
- Support email.

## Post-deployment checklist

- [ ] Add production OAuth callback URLs.
- [ ] Add Polar webhook URL: `https://myapp.example.com/api/auth/polar/webhooks`.
- [ ] Run migrations.
- [ ] Test signup/login/password reset.
- [ ] Test checkout and success-page sync in the intended Polar environment.
- [ ] Test file upload provider.
- [ ] Verify sitemap, robots, and Open Graph metadata.
