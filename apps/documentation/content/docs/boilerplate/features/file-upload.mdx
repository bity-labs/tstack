title: "File Upload"
description: "Use database uploads locally or DigitalOcean Spaces in production."
---

The boilerplate currently uses `uploadImage` from `src/lib/file-upload.ts` for profile-image style uploads.

## Providers

| Provider | Env value | Best for | External service |
| --- | --- | --- | --- |
| Database | `database` | Local development and prototypes | No |
| DigitalOcean Spaces | `digitalocean` | Production object storage | Yes |

The default is database storage.

```sh
FILE_UPLOAD_PROVIDER=database
MAX_FILE_SIZE_MB=1
```

## DigitalOcean Spaces

```sh
FILE_UPLOAD_PROVIDER=digitalocean
DIGITALOCEAN_SPACES_ENDPOINT=https://ams3.digitaloceanspaces.com
DIGITALOCEAN_SPACES_REGION=ams3
DIGITALOCEAN_SPACES_BUCKET=my-app-uploads
DIGITALOCEAN_SPACES_ACCESS_KEY_ID=...
DIGITALOCEAN_SPACES_SECRET_ACCESS_KEY=...
DIGITALOCEAN_SPACES_CDN=https://my-app-uploads.ams3.cdn.digitaloceanspaces.com
```

The endpoint should be the region endpoint only; do not include the bucket name.

## Usage

```ts
import { uploadImage } from "@/lib/file-upload";

const imageUrl = await uploadImage(file, user.id);
```

Use an authenticated action and validate file type and size before uploading.

## Security notes

- Validate on both client and server.
- Keep download routes access-aware if you add private files.
- Database storage is convenient but not recommended for production workloads.
- DigitalOcean uploads use environment/user-prefixed paths and sanitized filenames.
