---
title: "Analytics"
description: "Use Umami, PostHog, or no analytics through a single configuration switch."
---

The boilerplate supports Umami, PostHog, or disabled analytics through `NEXT_PUBLIC_ANALYTICS_PROVIDER`.

## Provider options

```sh
NEXT_PUBLIC_ANALYTICS_PROVIDER=umami
NEXT_PUBLIC_ANALYTICS_PROVIDER=posthog
NEXT_PUBLIC_ANALYTICS_PROVIDER=none
```

## Umami

```sh
NEXT_PUBLIC_ANALYTICS_PROVIDER=umami
NEXT_PUBLIC_UMAMI_WEBSITE_ID=your-website-id
NEXT_PUBLIC_UMAMI_HOST=https://cloud.umami.is
```

The script is conditionally rendered by `src/components/analytics/analytics-script.tsx`.

## PostHog

```sh
NEXT_PUBLIC_ANALYTICS_PROVIDER=posthog
NEXT_PUBLIC_POSTHOG_KEY=phc_your_project_key
NEXT_PUBLIC_POSTHOG_HOST=https://eu.posthog.com
```

PostHog is initialized from `src/instrumentation-client.ts`.

## Tracking events

Use `captureEvent` from `src/lib/tracking.ts` instead of importing provider SDKs from feature code:

```ts
import { captureEvent } from "@/lib/tracking";

captureEvent("signup_completed", { source: "pricing" });
```

## Event guidelines

- Use stable `snake_case` event names.
- Track meaningful product behavior, not every click.
- Avoid personally identifiable information unless you have a deliberate policy.
- Keep provider-specific logic out of features.
