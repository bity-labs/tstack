The boilerplate app lives at `apps/boilerplate` inside the TStack monorepo. In a standalone extraction, the paths below are relative to the standalone app root.

## Top-level app structure

```txt
apps/boilerplate/
├── src/app/        # Next.js App Router routes and route groups
├── src/features/   # Feature modules with public APIs
├── src/lib/        # Cross-cutting integrations and server utilities
├── src/components/ # Shared app components and UI primitives
├── src/config/     # Environment, routes, and wallet config
├── src/locales/    # Centralized user-facing copy and metadata
├── src/test/       # Test setup and Prisma mocks
├── prisma/         # Prisma schema and migrations
├── polar/          # Polar product and meter JSON configuration
├── content/blog/   # Sample MDX blog content
└── docs/           # Agent-facing boilerplate docs
```

## App Router route groups

```txt
src/app/
├── (auth)/       # Login, signup, forgot-password, reset-password
├── (landing)/    # Pre-launch landing page and email capture
├── (marketing)/  # Public home, pricing, blog, legal pages
├── (protected)/  # Dashboard, account, billing, usage, checkout success
└── api/          # API route handlers
```

Route groups organize code without changing URL paths. Route constants live in `src/config/routes.ts`.

## Feature modules

Feature code lives under `src/features/{feature-name}` and exposes stable imports through `index.ts`.

```txt
src/features/{feature-name}/
├── index.ts
├── models/
├── schemas/
├── services/
├── queries/
├── actions/
├── hooks/
└── components/
```

Create only the folders a feature needs. Simple features may stay flatter.

## Current feature modules

| Feature | Purpose |
| --- | --- |
| `authentication` | Login, signup, reset password, Email OTP, OAuth, SIWE UI and schemas. |
| `billing` | Polar products/meters, checkout data, subscription state, credits, usage, and order history. |
| `benefits` | Downloadables and GitHub repository benefits for one-time purchases. |
| `blog` | Velite/MDX content rendering for sample blog content. |
| `newsletter` | Landing page email capture. |
| `settings` | Account profile, password, email, profile image, and account deletion flows. |

## Public API rule

Import features from their public API when calling from pages or other features:

```ts
import { BillingOverview, getBillingOverviewQuery } from "@/features/billing";
```

If infrastructure code needs a server-only slice, use a narrow `server-api.ts` like `src/features/billing/server-api.ts` instead of importing UI, hooks, and route-facing modules.
