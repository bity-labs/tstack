Email/password authentication is enabled through Better Auth and uses React Email templates for verification and reset messages.

## Implementation map

```txt
src/features/authentication/
├── components/login.tsx
├── components/signup.tsx
├── components/forgot-password.tsx
├── components/reset-password.tsx

src/app/(auth)/
├── login/page.tsx
├── signup/page.tsx
├── forgot-password/page.tsx
└── reset-password/page.tsx
```

## Server configuration

`src/lib/auth/config.ts` enables email/password and email verification. Auth email callbacks live in `src/lib/auth/email-hooks.ts` and dispatch typed messages through `src/lib/email/send-email.ts`.

## Signup flow

1. User submits `/signup`.
2. Better Auth creates the account.
3. Verification email is sent.
4. User clicks the verification link.
5. The user is signed in after verification and redirected.

## Login flow

1. User submits `/login` with email and password.
2. Better Auth validates credentials.
3. Unverified users see a verification state with resend support.
4. Verified users are redirected to the configured callback route.

## Password reset

- `/forgot-password` requests a reset email.
- `/reset-password?token=...` accepts the token and new password.
- Reset email templates live in `src/components/emails/`.

## Account settings

Authenticated users can change email and password from the settings feature. Change-email verification is handled by `src/lib/auth/user-hooks.ts` and `src/lib/auth/email-hooks.ts`.

## Environment required

- `BETTER_AUTH_SECRET`
- `BETTER_AUTH_URL`
- `PROJECT_URL` or `NEXT_PUBLIC_SITE_URL`
- `RESEND_API_KEY` and `EMAIL_FROM_ADDRESS` for production email delivery
