The boilerplate sends transactional email through a provider-agnostic dispatcher in `src/lib/email/send-email.ts`.

## Architecture

| File | Purpose |
| --- | --- |
| `src/lib/email/types.ts` | `EmailMessage` and `EmailResult` unions. |
| `src/lib/email/send-email.ts` | Renders templates and sends/logs messages. |
| `src/lib/email/resend-client.ts` | Resend client factory. |
| `src/lib/auth/email-hooks.ts` | Better Auth callbacks adapted to email messages. |
| `src/components/emails/` | React Email templates. |

## Built-in message types

- OTP verification code.
- Email verification and change-email verification link.
- Password reset link.
- Account deletion confirmation link.

## Local vs production behavior

In development, messages are rendered and logged for debugging. In production, messages are sent through Resend using `RESEND_API_KEY` and `EMAIL_FROM_ADDRESS`.

## Sending a message

```ts
import { sendEmail } from "@/lib/email/send-email";

const result = await sendEmail({
  type: "verification",
  to: "user@example.com",
  data: {
    token: "token-value",
    url: "https://myapp.example.com/verify?token=token-value",
  },
});

if (!result.success) {
  // Decide whether this boundary should throw, retry, or show an error.
}
```

## Add a custom email

1. Create a React Email template under `src/components/emails/`.
2. Export it from `src/components/emails/index.ts`.
3. Add a variant to `EmailMessage` in `src/lib/email/types.ts`.
4. Render it in the dispatcher switch.
5. Call `sendEmail` from a server action, route, service, or auth hook.
