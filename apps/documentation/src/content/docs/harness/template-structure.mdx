The standalone harness template lives at `packages/harness/templates/default`.

```txt

├── AGENTS.md
├── docs/
│   ├── context.md
│   ├── coding-standards.md
│   ├── architecture.md
│   ├── design.md
│   ├── adr/
│   │   └── 0000-template.md
│   └── engineering/
│       ├── index.md
│       ├── architecture-boundaries.md
│       ├── code-review.md
│       ├── data-modeling.md
│       ├── debugging.md
│       ├── deep-modules.md
```

## Root instructions

`AGENTS.md` is the entrypoint for coding agents. It tells agents which docs to read, how to find source of truth, and what working rules apply before editing.

## Project context

`docs/context.md` captures durable product and domain language. Customize it before relying on the harness for product work.

## Coding standards

`docs/coding-standards.md` captures repository-specific implementation expectations, validation commands, and dependency policy.

## ADRs

`docs/adr/0000-template.md` provides a starting format for architecture decision records. Create new ADRs when a decision affects architecture, ownership, or long-term constraints.

## Engineering doctrine

`docs/engineering/` contains reusable guidance for design, testing, debugging, review, refactoring, security, and domain modeling. Agents should load the files relevant to the current task instead of reading everything by default.

## Skills

`.agents/skills/` contains workflow instructions for repeatable agent tasks. Each skill has its own `SKILL.md` and may include supporting templates.

## Pi agents and prompts

`.pi/agents/` defines Pi-specific sub-agents and `.pi/prompts/` defines Pi slash-command prompts. The default template defines only the `planner` execution planner; implementation, review, and recon use the bundled pi-subagents builtin agents with role boundaries configured through `subagents.agentOverrides` (see the `setup-pi-subagents` skill). `/autoshift` is the tiered autonomous implementation workflow, and `docs/engineering/roles.md` records the role policy.

Optional specialist agents live in separate template overlays (`templates/pi-notes`, `templates/pi-research` in the TStack source) so a default install stays minimal; agent discovery is recursive, so optional agents must not sit inside the installed `.pi/agents/` directory.

## Copy vs symlink policy

For normal installs, copy the entire template into the target project so the project works in isolation.

Inside the TStack monorepo only, harness-owned resources may be symlinked while dogfooding:

- `.agents`
- `.pi/agents`
- `.pi/prompts`
- `docs/engineering`

Project-owned working documents should stay as real files and be customized per project:

- `AGENTS.md`
- `docs/context.md`
- `docs/coding-standards.md`
- `docs/adr/**`

The root monorepo currently uses these two symlinks. The new boilerplate app directories are placeholders; no app-level harness wiring has been implemented yet.
